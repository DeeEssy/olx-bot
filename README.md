# OLX Telegram Bot

Бот моніторить оголошення на [olx.ua](https://www.olx.ua/uk/) для обраного
міста і надсилає в Telegram нові оголошення, що підходять під задані фільтри
(ціна, кількість кімнат, тварини, тип власника). Підтримує два незалежні
потоки з окремими chat_id та фільтрами: **оренда** та **продаж** квартир.

## Як це працює

OLX віддає повний список оголошень (фото, ціна, район, поверх, тварини,
опис, дата, тип власника) прямо в HTML сторінки пошуку у вигляді вбудованого
JSON (`window.__PRERENDERED_STATE__`) — бот скачує цю сторінку і парсить
його, окремий API не потрібен.

Бот кожні `POLL_INTERVAL_SECONDS` (за замовчуванням 5 хв) сканує перші
`PAGES_TO_SCAN` сторінок пошуку, відкидає оголошення, які вже надсилались
раніше (зберігаються в SQLite `data/olx_bot.db`), застосовує фільтри з
`.env` і надсилає нові збіги в Telegram: спочатку альбом фото, потім текстове
повідомлення з деталями і кнопкою "Відкрити оголошення" (посилання на OLX).

### Важливо: обхід захисту OLX від ботів

OLX захищений від ботів на рівні CloudFront, яка фільтрує запити за
TLS-відбитком (JA3/JA4). Звичайні Python-бібліотеки (aiohttp, requests) і
навіть системний `curl` отримують 403 — перевірено як на Windows, так і на
чистому Linux (GitHub Actions runner). Працює лише
[`curl_cffi`](https://github.com/lexiforest/curl_cffi), яка імітує
справжній TLS-відбиток браузера Chrome — тому запити в `bot/scraper.py`
йдуть саме через неї. Ніяких додаткових системних залежностей (Git for
Windows тощо) не потрібно — все ставиться через `pip install -r requirements.txt`,
і бот однаково працює і на Windows, і на будь-якому Linux-хостингу.

## Встановлення

```powershell
py -m pip install -r requirements.txt
```

## Налаштування

1. Скопіюй `.env.example` в `.env`.
2. Створи бота в [@BotFather](https://t.me/BotFather) командою `/newbot`,
   встав отриманий токен у `TELEGRAM_BOT_TOKEN`.
3. Заповни `.env`:
   - `CITY_SLUG` — місто у форматі URL olx.ua (наприклад `kiev`, `odessa`,
     `lvov`, `kharkov`, `dnepr`, `vinnitsa`, `nikolaev`, `zaporozhe` тощо —
     зазвичай російська транслітерація назви міста).
   - `PRICE_MIN` / `PRICE_MAX` — діапазон ціни в грн.
   - `ROOMS` — кількість кімнат через кому, наприклад `1,2`. Порожньо —
     без обмежень.
   - `PETS_ONLY` — `true`, якщо показувати тільки оголошення, де прямо
     дозволені тварини.
   - `OWNER_TYPE` — `any` / `agency` / `private`.
   - `MAX_AGE_DAYS` — не показувати оголошення старіші за N днів (захист від
     "піднятих" старих оголошень). 0 — вимкнути перевірку.

   Це все — фільтри потоку **оренди**. Якщо потрібен ще й потік **продажу**
   квартир (окремий chat_id, окремі фільтри), заповни аналогічні
   `TELEGRAM_CHAT_ID_SALE`, `SALE_PRICE_MIN/MAX`, `SALE_ROOMS`,
   `SALE_OWNER_TYPE`, `SALE_MAX_AGE_DAYS`. Якщо `TELEGRAM_CHAT_ID_SALE`
   лишити порожнім — потік продажу просто вимкнений.
4. Запусти бота (`py main.py`) і напиши йому в Telegram що завгодно — він
   відповість твоїм `chat_id`. Встав це значення в `TELEGRAM_CHAT_ID` в
   `.env` і перезапусти бота.

## Запуск

```powershell
py main.py
```

Бот працюватиме в циклі, поки процес не зупинено (Ctrl+C). Для постійної
роботи запускай його як фонову задачу / службу Windows (наприклад через
Планувальник завдань з дією "При вході в систему").

## Перевірка фільтрів без відправки в Telegram

```powershell
py dry_run.py
```

Скрипт скачає поточні сторінки пошуку і покаже, скільки оголошень
проходять фільтри з `.env`, а також приклад повідомлення для перших з них.

## Структура проєкту

```
config.py          - завантаження налаштувань з .env
bot/scraper.py      - скачування сторінок OLX і парсинг оголошень
bot/filters.py       - нормалізація полів оголошення + перевірка фільтрів
bot/formatter.py     - формування тексту повідомлення для Telegram
bot/db.py            - SQLite: які оголошення вже надіслані
bot/runner.py         - один цикл сканування + відправки (спільний для main.py і run_once.py)
main.py              - постійний цикл (для локального запуску) + обробник /start для chat_id
run_once.py           - одноразовий прогін циклу (для GitHub Actions)
dry_run.py           - ручна перевірка фільтрів без відправки в Telegram
```

## Запуск через GitHub Actions (безкоштовно, без свого ПК)

Замість постійно працюючого процесу на своєму комп'ютері бот може жити в
GitHub Actions: workflow `.github/workflows/olx-bot.yml` запускає
`run_once.py` за розкладом (кожні ~10 хв — точний час не гарантований,
GitHub може затримувати cron на кілька хвилин під навантаженням) і
комітить назад у репозиторій файл `data/state.db` — без цього кожен запуск
не пам'ятав би, що вже надсилалось.

Налаштування:

1. Запуш цей репозиторій на GitHub (файл `.env` в git не потрапить — він в
   `.gitignore`).
2. У репозиторії: **Settings → Secrets and variables → Actions**.
   - Вкладка **Secrets** → New repository secret:
     - `TELEGRAM_BOT_TOKEN` — токен бота.
   - Вкладка **Variables** → New repository variable (все, крім токена, не
     секретне, тому як variables):
     - `TELEGRAM_CHAT_ID`
     - `CITY_SLUG`
     - `CITY_NAME` (необов'язково)
     - `PRICE_MIN`, `PRICE_MAX` (необов'язково)
     - `ROOMS` (необов'язково)
     - `PETS_ONLY` (`true`/`false`)
     - `OWNER_TYPE` (`any`/`agency`/`private`)
     - `PAGES_TO_SCAN` (необов'язково, за замовчуванням 3)
     - `MAX_AGE_DAYS` (необов'язково, за замовчуванням 3)
     - Для потоку продажу (необов'язково, вимкнено якщо `TELEGRAM_CHAT_ID_SALE`
       порожній): `TELEGRAM_CHAT_ID_SALE`, `SALE_PRICE_MIN`, `SALE_PRICE_MAX`,
       `SALE_ROOMS`, `SALE_OWNER_TYPE`, `SALE_MAX_AGE_DAYS`
3. Вкладка **Actions** у репозиторії → workflow "OLX bot poll" → **Run
   workflow**, щоб перевірити вручну, не чекаючи розкладу.

Якщо після цього бот одночасно ганяється і локально (`py main.py`), і в
Actions — вони не знають одне про одного і ведуть окремі бази `data/olx_bot.db`
/ `data/state.db`, тому можуть надіслати одне й те саме оголошення двічі.
Тримай активним щось одне.

**Обмеження безкоштовного тарифу:** GitHub автоматично вимикає заплановані
(schedule) workflow, якщо в репозиторії 60 днів не було жодного коміту.
Оскільки бот сам комітить `data/state.db` при кожній знахідці нового
оголошення, це на практиці рідко стається — але якщо оголошень довго немає,
може знадобитись зайти і натиснути "Run workflow" вручну або зробити будь-який
коміт.
